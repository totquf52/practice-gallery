# 기획 문서 고칠 때 규칙

- **PRD는 출처를 함께 적는다.** `PRD.md`의 모든 줄은 어디서 온 내용인지로 끝난다 — `(user.md)`, `(scope.md 5)`, `(wireframe.png 화면 1)`. 새로 쓰거나 고친 줄에도 같은 출처를 붙일 것. 기획이 `idea/`까지 되짚어지는 건 이 표기 덕분이다.
- `flow.md`와 `PRD.md`에 같은 mermaid 흐름도가 두 번 들어 있다. 한 번 어긋난 적이 있다(`flow.md`는 화면 3으로 들어가는 버튼이 없다고 적어 두었고, PRD가 [제목 넣기]를 넣어 그 문제를 정리했다). 고칠 때는 둘을 같이 고칠 것.
- **`idea/`는 메모 모음이 아니라 이어지는 차례다**: `problems.md` → `shortlist.md` → `user.md` → `ipo.md` → `scope.md` → `flow.md` → `PRD.md`. 뒤쪽 문서를 고치면 앞쪽 문서가 그걸 여전히 받쳐 주는지 확인할 것. `scope.md`에는 기능 후보가 17개 적혀 있고 `PRD.md` 3장이 그중 6개를 골라 나머지를 비목표로 따로 적어 둔다 — 버린 항목도 지우지 말고 보이게 남길 것.
